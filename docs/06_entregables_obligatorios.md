# 5. Entregables Obligatorios en el Proyecto

Alineado exactamente con las especificaciones de la cátedra de Ingeniería del Software I, el proyecto se compromete a entregar los siguientes puntos evaluativos organizados en la siguiente matriz:

| Entregable Obligatorio | Descripción / Evidencia en el Proyecto | Estado |
| :--- | :--- | :---: |
| **a. Aplicación funcional** | Sistema PWA operativo (Frontend + Backend) permitiendo el flujo completo: autenticación, creación de pases híbridos, validación en portería y auditoría. | En progreso (Sprint 3) |
| **b. GitHub organizado** | Repositorio estructurado y limpio. **Debe incluir:**<br>➤ **README:** Documentación general del propósito del proyecto.<br>➤ **Arquitectura:** Documento con el diagrama ER, roles y stack tecnológico.<br>➤ **Setup:** Instrucciones de instalación local y variables de entorno. | En progreso |
| **c. Base de datos documentada** | Documentos de diseño (`02_diseno.md`) que incluyen el Diagrama Entidad-Relación y el Diccionario de Datos detallado (7 entidades normalizadas). Autorización gestionada por middleware, no por RLS. | **Listo** |
| **d. Automatización funcionando** | Integración probada de **Gemini API** para lectura de cédulas (OCR) y flujos de **n8n** para disparar notificaciones automatizadas al residente. | Pendiente |
| **e. Deploy público** | Aplicación desplegada en la nube utilizando **Vercel**, accesible mediante una URL pública para que el docente la pueda evaluar sin compilar. | Pendiente |
| **f. Presentación final** | Material visual (Diapositivas) para la defensa oral del proyecto, resumiendo el problema, la metodología ágil y la arquitectura serverless. | Pendiente |
